# v0.5.4-beta Release Dispositions (MTIX-95.52)

Per docs/RELEASE-CHECKLIST.md section 1: every finding deferred since the
last tag is dispositioned before the next release. This note records what
v0.5.4-beta ships, what moved to 0.6.0 and why, and which review
follow-ups stay open. It was written against `main` at 47d44f7 and the
task board as of 2026-10-03. Each row names its ticket; the merge for each
shipped row is a `loop merge MTIX-...` commit (or a named merge) in the
history of `main`, and CHANGELOG.md carries the user-facing text.

Scope rule (recorded on MTIX-95.9, 2026-10-01): only S0/S1 data-loss or
security findings and release mechanics block 0.5.4. A new finding
defaults to 0.6.0.

## 1. What 0.5.4-beta ships

v0.5.4-beta is cut from `main` (decision recorded on MTIX-95.9,
2026-09-26), so it carries the MTIX-95 phase-0 containment and security
work and the features merged since v0.5.3-beta.

### Relay, experimental

The FR-21 file relay (MTIX-64 series, MTIX-79) is on `main`. It ships
marked experimental and opt-in (MTIX-95.48): nothing changes unless
`sync.relay.dir` is set, its behavior and on-disk format may change in
0.6.0, and its live release gate is not complete (section 2).

## 2. What moved to 0.6.0, and why

| Ticket | Disposition |
|--------|-------------|
| MTIX-95.31.15 | First pull after upgrading from 0.5.3 or earlier is refused as lossy for history an older board never carried. Four review rounds found silent drops whenever the import guessed which differences were a teammate's, so the heuristic approach was abandoned for a design. 0.5.4 keeps the safe refusal and its documented way out. |
| MTIX-95.31.18 | A per-task record of the last exchanged board is needed to tell a local change from a teammate's one. It needs the snapshot design that is decided together with the merge-base approach, so it does not ship in a patch. |
| MTIX-95.31.19 | A complete, timestamped per-task change log. It is a feature request that gives conflict resolution real evidence, not a fix for a defect in 0.5.4. |
| MTIX-112 | Inbox features (unbounded wait, a written retention guarantee, delivery status, pattern docs). New functionality, outside the scope freeze. |
| MTIX-64.9 | The relay live release gate (end-to-end scenarios, traceability entries, fault-injection additions). It must run before the relay loses its experimental label. |
| MTIX-107.77 | Regeneration of the stale generated docs. Done in this change: docs/TROUBLESHOOTING.md and docs/STATUS_MACHINE.md carry the 0.5.4-beta stamp and match the generator. The drift check the ticket also asks for is not added here and stays for 0.6.0. |

## 3. Open review follow-ups

Follow-ups filed from independent reviews are tickets, not silent fixes.
On 2026-10-03 the board holds 293 nodes that are open, in progress,
blocked or deferred (222 open, 62 in progress, 8 blocked, 1 deferred).
Of those:

- 80 are titled "S2 follow-up" or "S3 follow-up" (8 S2, 72 S3), filed from
  review rounds. The largest groups sit under MTIX-95.31 (19), MTIX-95.18
  (7) and one to four each under MTIX-95.2, 95.5, 95.10, 95.14, 95.15,
  95.16, 95.17, 95.20, 95.22, 95.23, 95.26, 95.27, 95.37 and 95.47. None is
  titled S0 or S1. Each carries its own finding and mutation list; they
  target 0.6.0 unless re-triaged.
- Five review follow-ups under MTIX-95.1 move to 0.6.0: MTIX-95.1.4.2,
  95.1.4.4, 95.1.4.6, 95.1.7.1 and 95.1.8.2. They are minor review
  follow-ups for tests and wording, not release blockers, and each is
  labelled 0.6.0 on the board. Their titles stay neutral until after the
  release.
- Parents that stay open for their children: MTIX-95 (128 nodes in the
  tree are open, in progress, blocked or deferred), MTIX-95.1 and MTIX-95.31.

The release ticket for this change (MTIX-95.52) and the release epic
(MTIX-95.9, blocked until the tag and publication) close after the tag.

Release outcome: every deferred finding is either shipped, moved to 0.6.0
with its reason, or open under a named ticket. Nothing carries silently
across the release boundary.
